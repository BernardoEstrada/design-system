# AGENTS.md

How to pick up work on this repo. Written for coding agents (Claude Code, Codex, Cursor, …) and humans alike. `README.md` is the consumer-facing doc; this file covers how the repo works and how to change it safely.

## What this is

`@bernardoestrada/design-system`: a personal React component library and theme collection, published to **GitHub Packages**. Apps consume it via `yarn add @bernardoestrada/design-system` or start from the `create-webapp` scaffolder.

The repo ships two packages from one tag:

| Package | Source | Purpose |
|---|---|---|
| `@bernardoestrada/design-system` | repo root (`src/`) | Components, themes, icons, compiled CSS |
| `@bernardoestrada/create-webapp` | `create-webapp/` | CLI that degits `templates/react-app` into a new app |

## Stack

- React 18 + TypeScript + Vite (library mode, ESM + CJS)
- Tailwind CSS v4 + DaisyUI v5, CSS-first config (no `tailwind.config.js`)
- Storybook 10 (`@storybook/react-vite`)
- Yarn 4.18.1 via Corepack, `nodeLinker: node-modules`
- No unit test suite. Verification = typecheck + lint + build + looking at it in Storybook.

## Commands

```bash
corepack enable        # once, so `yarn` is 4.18.1
yarn                   # install
yarn dev               # Storybook on :6006
yarn typecheck
yarn lint
yarn build             # gen icons → tsc -b → vite build into dist/
yarn build-storybook
yarn icons             # regenerate src/icons/ from installed packages
yarn icons:update      # upgrade icon packages (quarantine-aware) + regenerate
yarn icons:update --check     # just report newer versions
yarn icons:update --metadata  # re-fetch Lucide metadata only
```

**Before calling work done, run `yarn typecheck && yarn lint && yarn build`.** That is exactly what CI (`.github/workflows/ci.yml`) runs. For UI changes, also open the story in Storybook and check it in at least one dark app theme (`navigator-dark`), one light theme, and `neobrutalism`. Those three families restyle components the most.

## Rules

- **Don't commit until the owner approves the changes**, unless they've told you to in this session. When you do commit, use Conventional Commits (`feat:`, `fix:`, `chore:`, `feat!:`); see `git log` for the tone.
- **Don't pin dependencies.** Use caret ranges (`^1.62.0`), never exact versions.
- **Respect the 24-hour quarantine.** `.yarnrc.yml` sets `npmMinimalAgeGate`; never raise a dependency to a version published less than a day ago. `yarn icons:update` already respects it.
- **Install with `yarn`, not npm.** Keep `yarn.lock` in Yarn 4 format; CI uses `yarn install --immutable`, so a stale lockfile fails the build. (`create-webapp/` is the exception: it has its own `package-lock.json` because it's published with npm.)
- **Never hand-edit `src/icons/`.** It is generated by `scripts/gen-icons.mjs`. It's committed, but regenerated on every build.
- **Never edit `dist/` or `storybook-static/`.** Both are build output and gitignored.
- **Breaking changes bump the minor version while on 0.x.** Removing an export, renaming a prop, or dropping icons (apps may store icon names) counts.

### Package entry points

Defined in `package.json` `exports` and `vite.config.ts` `build.lib.entry`. Adding an entry point means touching both, plus the README table.

| Import | Source |
|---|---|
| `.` | `src/index.ts` |
| `./styles` | compiled `dist/index.css` |
| `./icons`, `./icons/<pack>`, `./icons/dynamic`, `./icons/react-icons` | `src/icons/*.ts` (generated; list in `src/icons/entries.json`) |
| `./icon-picker` | `src/icon-picker.ts` |

`lucide-react`, `@lucide/lab` and `react-icons` are **external** in the Vite build so consumers tree-shake per icon. Don't bundle them.

## Components

Conventions, based on the existing components (see `ChipGroup`, `ColorPicker`, `Toggle`):

- Function components, named export, props interface in the same file. Doc-comment the component and any non-obvious prop.
- Build on DaisyUI classes (`btn`, `input`, `modal`, …) and theme tokens (`bg-base-100`, `text-primary`, `var(--color-*)`). **No hard-coded colours**: every component must look right in all 40+ themes.
- Join classes with `cx()` from `src/utils/cx.ts`; accept and merge a `className` prop.
- Native-input form controls (`Input`, `Select`, `Textarea`, `Checkbox`, `Radio`, `Toggle`) forward refs (`forwardRef`) so they work with react-hook-form. New ones should too.
- Icons come in as `ReactNode` props (`icon`, `iconOn`, …). Inside components, import from `lucide-react` directly.
- Accessibility: real `<button type="button">`, `aria-pressed` / `aria-label` / roles as needed, visible focus.
- Mobile: popovers that would be cramped become bottom sheets under 640 px (see `IconPicker`).

**Adding a component:**
1. `src/components/Name/Name.tsx` and `Name.stories.tsx`. Story `title` uses one of the existing groups (`Forms/`, `Feedback/`, `Overlays/`, `Navigation/`, `Display/`, `Components/`), plus `tags: ["autodocs"]`.
2. Export it (and its public types) from `src/index.ts` under the right group comment.
3. Add it to the Components table in `README.md`, with a usage snippet if the API isn't obvious.
4. If DaisyUI needs a fix for every theme, put it in `src/styles/components.css`. If only an app theme needs it, put it in `overrides.css` or that theme's CSS file.

Stories don't need their own theme wrapper. The global decorator in `.storybook/preview.tsx` calls `applyTheme()` on `<html>` from the toolbar's theme/appearance globals.

## Themes

Themes are applied with `data-theme` on `<html>`. A **theme family** (a `Themes` enum value such as `navigator`) maps to concrete **theme ids** per appearance (`navigator-light`, `navigator-dark`). `applyTheme(family, appearance)` resolves the right id.

| Category | Families | CSS |
|---|---|---|
| `app` | navigator, command, neobrutalism, neobrutalism-yellow | Full token set **plus** component-level vars (`--glass-*`, `--btn-*`, `--field-*`, `--badge-*`, `--modal-*`). Navigator/command styling lives in `styles/overrides.css`; neobrutalism styles its own components inside `neobrutalism.css`. |
| `editor` | vsdark, monokai, editor-nord, githublight, terminal, crt1990, win95, macclassic | Colour tokens only. Shared radii/depth are set once in `src/index.css`. Ported from DaisyUI v3 objects in `../BernardoEstrada.github.io/daisyui-themes.js`. |
| `daisyui` | every DaisyUI built-in | `@plugin "daisyui" { themes: all; }` |

Navigator/command were ported from `../wendid/frontend/src/styles/themes/`.

**Adding a theme:**
1. `src/themes/mytheme.css` containing `[data-theme="mytheme"] { color-scheme: …; --color-base-100: oklch(…); … }`. Add `-light` / `-dark` ids if it has both.
2. `@import` it in `src/index.css` (in its category's section).
3. Add it to the `Themes` enum **and** `CategorizedThemes` in `src/themes/index.ts`. Add a `name` when title-casing the id would be wrong (`"CRT 1990"`, `"GitHub Light"`). `listThemes()`, `ThemePicker` and the Storybook toolbar all read from `CategorizedThemes`.
4. Add it to the themes table in `README.md`.

**Gotcha:** the app themes override `.bg-base-100` with `--glass-bg` (and `!important`). Anything that previews *another* theme inside the page, like `ThemePicker` cards, must paint with explicit `var(--color-base-100)` etc. rather than `bg-base-100`, or it inherits the page's glass background. Also use `oklch()` for new colours to match the existing themes.

## Icons pipeline

- `yarn icons` (`scripts/gen-icons.mjs`) reads installed `lucide-react`, `@lucide/lab` and `react-icons` and writes `src/icons/`:
  - `index.ts`: Lucide + Lab components. Lab icons are wrapped with `createLucideIcon`, and Lab icons Lucide already ships are skipped.
  - one file per react-icons pack (`fa.ts`, `md.ts`, …) and `entries.json`
  - the IconPicker search index (tags, categories, aliases) from `scripts/data/lucide-metadata.json`
- `yarn icons:update` is the **only** thing that touches the network. It upgrades the three packages to their newest quarantine-cleared versions, fetches Lucide metadata at the matching git tag, regenerates, and prints added/removed icons. If icons were removed, the release is breaking.
- Storybook skips react-docgen for `src/icons/` (see `.storybook/main.ts`). Without that, startup takes minutes.

## Releasing

Only release when the owner asks. The tag is the source of truth for both packages' versions, but keep the files in step so the repo matches what's published:

1. Bump `version` in `package.json`, `create-webapp/package.json` and `create-webapp/package-lock.json` (both `version` fields at the top).
2. On a minor bump, also raise `@bernardoestrada/design-system` in `templates/react-app/package.json` (e.g. `^0.9.0`).
3. Commit (`feat: …; release 0.9.0` or `chore: release 0.9.0`), then tag and push:
   ```bash
   git tag -a v0.9.0 -m "v0.9.0"
   git push origin main v0.9.0
   ```
4. `.github/workflows/release.yml` typechecks, lints, builds and publishes both packages to GitHub Packages.

## Open threads

Known loose ends as of v0.8.1 (Nov 2026). Update this list when you close one or find a new one.

- `templates/react-app` (and its GitHub workflows) still use Yarn 1 commands. It's undecided whether new apps should start on Yarn 4; ask before changing it.
- `lucide-react` is on `^1.62.0`. 1.63.0 added ~17 icons (`earbuds`, `laser`, `chart-radar`, …) and removed `archive-restore`. Running `yarn icons:update` picks it up, but that release removes an icon, so it's a breaking (minor) bump.
- No automated tests or visual regression yet; Storybook is the review surface.
